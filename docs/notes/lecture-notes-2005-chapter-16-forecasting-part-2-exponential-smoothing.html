Objectives

  • Produce an exponential smoothing forecast and explain what the smoothing factor \(\alpha\) does.
  • Produce an exponential smoothing with trend adjustment forecast and explain what \(\beta\) does.
  • Tune \(\alpha\) and \(\beta\) on the data, and say why a parameter tuned on the whole sample is not the same as one that would have worked in real time.
  • Recognise when a smoothing method is being beaten by a trend, and fix it.

Before Exam 1 you built forecasts by averaging the last few values. Two things were wrong with that, and you saw both on the CPI. A moving average forgets everything older than its window, and it remembers everything inside the window equally. Exponential smoothing fixes both with one parameter: it remembers everything, but with weights that shrink geometrically into the past. Then the trend-adjusted version fixes the lag you watched every average suffer on a rising series.

You have been submitting challenge forecasts for six weeks now. Bring your backtest tables. By the end of this note you should know whether to switch methods, and be able to say why in two sentences.

Exponential Smoothing

Exponential smoothing adjusts the previous forecast by a fraction of the previous period’s forecasting error (Formula 16.2):

\[F_t = F_{t-1} + \alpha\,(A_{t-1} - F_{t-1}),\]

where \(F_t\) is the forecast for period \(t\), \(A_{t-1}\) the actual value in period \(t-1\), and \(\alpha\) the smoothing factor, \(0 \le \alpha \le 1\).

Read the formula as a sentence: next forecast = last forecast, corrected by a share of how wrong it was. If last quarter’s forecast was too low (positive error), the new forecast goes up; too high, it comes down. Donnelly calls it “self-correcting”. The size of the correction is \(\alpha\).

Do not confuse this \(\alpha\) with the \(\alpha\) of a hypothesis test. Same letter, no relation. Forecasters and hypothesis testers both got there first.

Priming the pump

To forecast period 13 you need the forecast for period 12, which needs the forecast for period 11, and so on back to period 1 — which has no earlier period. The convention is to set \(F_1 = A_1\) and start. That first “forecast” was assigned, not calculated, so it gets no forecasting error and it is left out of the MAD. Leaving it in would hand the method a free zero and make the comparison with the moving averages unfair.

With Brandywine Ford’s sales and \(\alpha = 0.6\):

Show the code 
a = CAR_SALES.values
F2 = a[0] + 0.6 * (a[0] - a[0])

show_math(r"\begin{aligned} F_1 &= A_1 = %d \\ F_2 &= F_1 + 0.6\,(A_1 - F_1) = %d + 0.6\,(%d - %d) = %.1f \\ F_3 &= F_2 + 0.6\,(A_2 - F_2) = %.1f + 0.6\,(%d - %.1f) = %.1f \\ F_4 &= F_3 + 0.6\,(A_3 - F_3) = %.1f + 0.6\,(%d - %.1f) = %.1f \end{aligned}"
          % (a[0], a[0], a[0], a[0], F2, F2, a[1], F2, F3, F3, a[2], F3, F4))

\[\begin{aligned} F_1 &= A_1 = 97 \\ F_2 &= F_1 + 0.6\,(A_1 - F_1) = 97 + 0.6\,(97 - 97) = 97.0 \\ F_3 &= F_2 + 0.6\,(A_2 - F_2) = 97.0 + 0.6\,(142 - 97.0) = 124.0 \\ F_4 &= F_3 + 0.6\,(A_3 - F_3) = 124.0 + 0.6\,(108 - 124.0) = 114.4 \end{aligned}\]

Notice \(F_4\): the period-3 error was \(108 - 124 = -16\), so the forecast came down by \(0.6 \times 16 = 9.6\). That is the self-correction.

What \(\alpha\) does

A large \(\alpha\) carries most of the last error forward: the forecast chases the data and jumps around. A small \(\alpha\) barely reacts: the forecast is smooth and slow. The role is the same as the window length \(p\) in a moving average, and the right value depends on the data in the same way.

Show the code 
_ = forecast_plot(CAR_SALES, {"alpha = 0.2": exp_smooth(CAR_SALES, 0.2),
                              "alpha = 0.8": exp_smooth(CAR_SALES, 0.8)},
                  title="Figure 16.6: the effect of alpha on the forecast", ylab="Cars sold")

Why “exponential”? Unwind the formula once: \(F_t = \alpha A_{t-1} + (1-\alpha) F_{t-1}\). Unwind it again and \(F_{t-1}\) contains \(\alpha A_{t-2}\) weighted by \((1-\alpha)\); unwind again and \(A_{t-3}\) carries \((1-\alpha)^2\). Every past value is in the forecast, with weights \(\alpha, \alpha(1-\alpha), \alpha(1-\alpha)^2, \ldots\) — a weighted moving average over the whole history, with weights that decay exponentially. With \(\alpha = 0.6\) the value from four periods ago has weight 0.038. With \(\alpha = 0.1\) it still has weight 0.073.

Tuning \(\alpha\)

Since \(\alpha\) is a choice, choose it the way you chose \(p\): compute the MAD for a range of values and look.

The MAD is smallest at \(\alpha\) = 0.35, where it is 16.6 — the book eyeballs “around 0.35”. Even at its best, exponential smoothing does not catch the four-period moving average on this series (11.2). The seasonal pattern is the reason, and nothing in this note fixes it; that is Part 3.

A tuned parameter is a description of the past. The \(\alpha\) that minimises the MAD over 2022–2026 is the one that would have done best if you had known it in 2022, which you did not. Below we check whether a tuned \(\alpha\) still wins when it is chosen only from data available at the time. When it does not, the tuning has fitted noise. This is the single most useful habit you can take from this course into any job that involves a model.

Excel, for the record

Excel’s Data Analysis tool asks for a damping factor, not \(\alpha\). The damping factor is \(1 - \alpha\): enter 0.4 to get \(\alpha = 0.6\). The output column is offset by one row and begins with #N/A — that is period 1 having no forecast, which is correct. If you ask Claude to build the workbook, say “damping factor 0.4” and check that the first numeric cell is 97.

Exponential Smoothing with Trend Adjustment

Every method so far lags a trending series, because every one of them forecasts from a level and a trend keeps moving the level. The fix is to smooth two things: the level, and the change in the level.

Exponential smoothing with trend adjustment (Formulas 16.3–16.5):

\[\begin{aligned} F_t &= \text{FIT}_{t-1} + \alpha\,(A_{t-1} - \text{FIT}_{t-1}) && \text{the smoothed level} \\ T_t &= \beta\,(F_t - F_{t-1}) + (1-\beta)\,T_{t-1} && \text{the smoothed trend} \\ \text{FIT}_t &= F_t + T_t && \text{the forecast including trend} \end{aligned}\]

with \(\beta\), the trend smoothing factor, also between 0 and 1. Start with \(F_1 = A_1\), \(T_1 = 0\).

\(T_t\) is a weighted average of the most recent change in the level (\(F_t - F_{t-1}\), weighted \(\beta\)) and the accumulated trend so far (\(T_{t-1}\), weighted \(1-\beta\)). A large \(\beta\) believes the latest change; a small \(\beta\) believes the long-run drift. Then the forecast is the level plus one period’s worth of trend.

# Exponential Smoothing

::: {.blue}
**Exponential smoothing** adjusts the previous forecast by a fraction of the
previous period's forecasting error (Formula 16.2):

$$F_t = F_{t-1} + \alpha\,(A_{t-1} - F_{t-1}),$$

where $F_t$ is the forecast for period $t$, $A_{t-1}$ the actual value in
period $t-1$, and $\alpha$ the **smoothing factor**, $0 \le \alpha \le 1$.
:::

Read the formula as a sentence: *next forecast = last forecast, corrected by
a share of how wrong it was.* If last quarter's forecast was too low (positive
error), the new forecast goes up; too high, it comes down. Donnelly calls it
"self-correcting". The size of the correction is $\alpha$.

::: {.charcoal}
Do not confuse this $\alpha$ with the $\alpha$ of a hypothesis test. Same
letter, no relation. Forecasters and hypothesis testers both got there first.
:::

## Priming the pump

To forecast period 13 you need the forecast for period 12, which needs the
forecast for period 11, and so on back to period 1 — which has no earlier
period. The convention is to set $F_1 = A_1$ and start. That first "forecast"
was assigned, not calculated, so it gets no forecasting error and it is left
*out* of the MAD. Leaving it in would hand the method a free zero and make
the comparison with the moving averages unfair.

With Brandywine Ford's sales and $\alpha = 0.6$:

```{python}
#| label: es-math
#| output: asis
a = CAR_SALES.values
F2 = a[0] + 0.6 * (a[0] - a[0])
F3 = F2 + 0.6 * (a[1] - F2)
F4 = F3 + 0.6 * (a[2] - F3)
show_math(r"\begin{aligned} F_1 &= A_1 = %d \\ F_2 &= F_1 + 0.6\,(A_1 - F_1) = %d + 0.6\,(%d - %d) = %.1f \\ F_3 &= F_2 + 0.6\,(A_2 - F_2) = %.1f + 0.6\,(%d - %.1f) = %.1f \\ F_4 &= F_3 + 0.6\,(A_3 - F_3) = %.1f + 0.6\,(%d - %.1f) = %.1f \end{aligned}"
          % (a[0], a[0], a[0], a[0], F2, F2, a[1], F2, F3, F3, a[2], F3, F4))
```

Notice $F_4$: the period-3 error was $108 - 124 = -16$, so the forecast came
*down* by $0.6 \times 16 = 9.6$. That is the self-correction.

```{python}

error_table(CAR_SALES, es6).round(1)[["actual", "forecast", "error", "abs_error"]]
```

The forecast for 2019Q1 is `{python} num(es6.iloc[-1])` cars and the MAD is
`{python} num(mad(CAR_SALES, es6))` — averaged over eleven errors, periods 2
through 12. That is *worse* than every moving average from Part 1. Donnelly's
point, and it bears repeating: no method wins on every series. With this
$\alpha$ on this series, exponential smoothing loses.

## What $\alpha$ does

A large $\alpha$ carries most of the last error forward: the forecast chases
the data and jumps around. A small $\alpha$ barely reacts: the forecast is
smooth and slow. The role is the same as the window length $p$ in a moving
average, and the right value depends on the data in the same way.

```{python}
#| label: es-alpha-plot
_ = forecast_plot(CAR_SALES, {"alpha = 0.2": exp_smooth(CAR_SALES, 0.2),
                              "alpha = 0.8": exp_smooth(CAR_SALES, 0.8)},
                  title="Figure 16.6: the effect of alpha on the forecast", ylab="Cars sold")
```

Why "exponential"? Unwind the formula once: $F_t = \alpha A_{t-1} + (1-\alpha) F_{t-1}$.
Unwind it again and $F_{t-1}$ contains $\alpha A_{t-2}$ weighted by
$(1-\alpha)$; unwind again and $A_{t-3}$ carries $(1-\alpha)^2$. Every past
value is in the forecast, with weights $\alpha, \alpha(1-\alpha),
\alpha(1-\alpha)^2, \ldots$ — a weighted moving average over the *whole*
history, with weights that decay exponentially. With $\alpha = 0.6$ the value
from four periods ago has weight `{python} num(0.6 * 0.4**3, 3)`. With
$\alpha = 0.1$ it still has weight `{python} num(0.1 * 0.9**3, 3)`.

::: {.scarlet}
A tuned parameter is a *description of the past*. The $\alpha$ that minimises
the MAD over 2022–2026 is the one that would have done best *if you had known
it in 2022*, which you did not. Below we check whether a tuned $\alpha$ still
wins when it is chosen only from data available at the time. When it does not,
the tuning has fitted noise. This is the single most useful habit you can take
from this course into any job that involves a model.
:::

# Exponential Smoothing with Trend Adjustment

Every method so far lags a trending series, because every one of them
forecasts from a level and a trend keeps moving the level. The fix is to
smooth two things: the level, and the *change* in the level.

::: {.blue}
**Exponential smoothing with trend adjustment** (Formulas 16.3–16.5):

$$\begin{aligned}
F_t &= \text{FIT}_{t-1} + \alpha\,(A_{t-1} - \text{FIT}_{t-1}) && \text{the smoothed level} \\
T_t &= \beta\,(F_t - F_{t-1}) + (1-\beta)\,T_{t-1} && \text{the smoothed trend} \\
\text{FIT}_t &= F_t + T_t && \text{the forecast including trend}
\end{aligned}$$

with $\beta$, the trend smoothing factor, also between 0 and 1. Start with
$F_1 = A_1$, $T_1 = 0$.
:::

$T_t$ is a weighted average of the *most recent* change in the level
($F_t - F_{t-1}$, weighted $\beta$) and the *accumulated* trend so far
($T_{t-1}$, weighted $1-\beta$). A large $\beta$ believes the latest change; a
small $\beta$ believes the long-run drift. Then the forecast is the level plus
one period's worth of trend.

With $\alpha = 0.3$ and $\beta = 0.1$ (Table 16.6):

```{python}
#| label: est-table
est = exp_smooth_trend(CAR_SALES, alpha=0.3, beta=0.1)
tbl = est.round(1)
tbl.insert(0, "actual", list(CAR_SALES.values) + [np.nan])
tbl["abs_error"] = error_table(CAR_SALES, est)["abs_error"].round(1).reindex(tbl.index)
tbl
```

Follow one row. For period 3: the level $F_3 = 97.0 + 0.3(142 - 97.0) = 110.5$;
the trend $T_3 = 0.1(110.5 - 97.0) + 0.9(0) = 1.4$; the forecast
$\text{FIT}_3 = 111.9$. The last row is the forecast for 2019Q1:
`{python} num(est["FIT"].iloc[-1])` cars, MAD `{python} num(mad(CAR_SALES, est))`.
Better than plain exponential smoothing at $\alpha = 0.6$, still not better
than the four-period average. The trend is real but small (about 2.5 cars a
quarter), and the seasonal swings are ten times larger.

```{python}
#| label: summary-cars
pd.set_option("display.float_format", lambda v: f"{v:,.1f}")
accuracy(CAR_SALES, {
    "naive": naive_forecast(CAR_SALES),
    "SMA p=3": sma_forecast(CAR_SALES, 3),
    "SMA p=4": sma_forecast(CAR_SALES, 4),
    "WMA 3-2-1": wma_forecast(CAR_SALES, [1, 2, 3]),
    "ES alpha=0.6": es6,
    "ES+trend 0.3, 0.1": est,
}).round(1)
```

This is Donnelly's Table 16.7, with the naive row added and two extra
yardsticks. Read it as the book does: choose the four-period SMA, and do not
conclude that simple always beats sophisticated. It depends on the series, and
now we go to the series that matter.
