Downloading from FRED

FRED publishes every series at a public CSV endpoint that needs no API key, and the course module fred_tools.py wraps it. We use fred_frame, which fetches each series independently and reports what happened. That matters: a single bulk request for a dozen identifiers fails entirely if any one of them is misspelled or retired, which is a poor way to learn that one identifier was wrong.

Two things in that table are worth stopping on.

First, check the first column against the START date we asked for. We requested 1990, but FRED does not serve 1990 for every series — SP500, for instance, is only distributed with a rolling ten-year window. The start date you request is a ceiling, not a guarantee, and a model that silently uses whatever it got back will be fit on a much shorter sample than you intended.

Reconciling the frequencies

This is the step the R note never had to confront, because it stopped before downloading. Any model using these indicators together needs them on one clock. The defensible choice is to step down to the slowest frequency — monthly — rather than forward-filling monthly data onto daily rows, which would fabricate precision the source data does not have.

How you aggregate depends on what the series measures:

  • Levels and indexes (SP500, T10Y3M, UMCSENT, AWHMAN) — take the monthly mean, which is the standard convention for converting a high-frequency level to a monthly observation.
  • Flows (ICSA, initial claims) — these are counts accumulated over a week, so a monthly sum is the meaningful aggregate.
  • Already monthly — leave alone.
SUM_SERIES = {"ICSA"}

available = [c for c in raw.columns]
monthly = pd.DataFrame(index=raw.resample("MS").mean().index)

for sid in available:
    s = raw[sid].dropna()
    if fred_series[sid]["freq"] == "M":
        m = s.resample("MS").last()
    elif sid in SUM_SERIES:
        m = s.resample("MS").sum()
    else:
        m = s.resample("MS").mean()
    monthly[sid] = m

# How you measure "change" depends on what the series is.
#
# A percent change is only meaningful for a quantity that cannot be zero or
# negative. T10Y3M is a SPREAD: it crosses zero every time the yield curve
# inverts. A spread moving from -0.10 to +0.10 is not a "200% decline" -- that
# figure is arithmetic nonsense, and dividing by a value at or near zero
# produces infinities that poison everything downstream.
#
# For series that can cross zero, the meaningful change is a simple
# difference, in the series' own units.
crosses_zero = [c for c in monthly.columns if (monthly[c].dropna() <= 0).any()]

changes = pd.DataFrame(index=monthly.index)
for col in monthly.columns:
    if col in crosses_zero:
        changes[col] = monthly[col].diff()
    else:
        changes[col] = monthly[col].pct_change(fill_method=None)

changes = changes.replace([float("inf"), float("-inf")], float("nan"))

print(f"Percent changes : {[c for c in monthly.columns if c not in crosses_zero]}")
print(f"Differences     : {crosses_zero}  (these cross zero)")

corr = changes.corr(min_periods=24)

fig, ax = plt.subplots(figsize=(7.5, 6.5))
im = ax.imshow(corr.values, cmap="RdBu_r", vmin=-1, vmax=1)
ax.set_xticks(range(len(corr)), corr.columns, rotation=90, fontsize=8)
ax.set_yticks(range(len(corr)), corr.index, fontsize=8)
ax.grid(visible=False)
for i in range(len(corr)):
    for j in range(len(corr)):
        v = corr.values[i, j]
        if pd.notna(v):
            ax.text(j, i, f"{v:.2f}", ha="center", va="center", fontsize=6.5,
                    color="white" if abs(v) > 0.55 else "#333333")
fig.colorbar(im, ax=ax, shrink=0.8, label="correlation")
ax.set_title("Correlation of monthly percent changes")
fig.tight_layout()
plt.show()

Correlating the changes rather than the levels matters here. Most of these series trend, and correlating trending levels will report near-perfect relationships between quantities that have nothing to do with one another.

But “change” is not one thing. For an index or a level that stays positive, a percent change is the natural measure. For a spread, it is meaningless: T10Y3M is the gap between two yields and it goes negative whenever the curve inverts. Ask for a percent change there and you get figures like “-200%” for a move from -0.10 to +0.10, plus an infinity every time the denominator touches zero. One bad column is enough to make the entire correlation matrix uncomputable.

Before transforming a variable, ask what it measures. A ratio, a level, a spread, and a count do not all admit the same operations, and the code will not stop you from applying the wrong one.

What to take from this

  1. The series IDs are the easy part. Reconciling frequency and coverage is where the actual work is, and it is invisible until you download.
  2. start= is a request, not a promise. Always verify the window you got.
  3. Aggregate flows by summing and levels by averaging — the choice is determined by what the series measures, not by convenience.
  4. Correlate changes, not levels, unless you have a reason to do otherwise.

```{python}
# produces infinities that poison everything downstream.
#
# For series that can cross zero, the meaningful change is a simple
# difference, in the series' own units.
crosses_zero = [c for c in monthly.columns if (monthly[c].dropna() <= 0).any()]

changes = pd.DataFrame(index=monthly.index)
for col in monthly.columns:
    if col in crosses_zero:
        changes[col] = monthly[col].diff()
    else:
        changes[col] = monthly[col].pct_change(fill_method=None)

changes = changes.replace([float("inf"), float("-inf")], float("nan"))

print(f"Percent changes : {[c for c in monthly.columns if c not in crosses_zero]}")
print(f"Differences     : {crosses_zero}  (these cross zero)")

corr = changes.corr(min_periods=24)

fig, ax = plt.subplots(figsize=(7.5, 6.5))
im = ax.imshow(corr.values, cmap="RdBu_r", vmin=-1, vmax=1)
ax.set_xticks(range(len(corr)), corr.columns, rotation=90, fontsize=8)
ax.set_yticks(range(len(corr)), corr.index, fontsize=8)
ax.grid(visible=False)
for i in range(len(corr)):
    for j in range(len(corr)):
        v = corr.values[i, j]
        if pd.notna(v):
            ax.text(j, i, f"{v:.2f}", ha="center", va="center", fontsize=6.5,
                    color="white" if abs(v) > 0.55 else "#333333")
fig.colorbar(im, ax=ax, shrink=0.8, label="correlation")
ax.set_title("Correlation of monthly percent changes")
fig.tight_layout()
plt.show()
```

Correlating the *changes* rather than the levels matters here. Most of these
series trend, and correlating trending levels will report near-perfect
relationships between quantities that have nothing to do with one another.

But "change" is not one thing. For an index or a level that stays positive, a
percent change is the natural measure. For a **spread**, it is meaningless:
`T10Y3M` is the gap between two yields and it goes negative whenever the curve
inverts. Ask for a percent change there and you get figures like "-200%" for a
move from -0.10 to +0.10, plus an infinity every time the denominator touches
zero. One bad column is enough to make the entire correlation matrix
uncomputable.

::: {.scarlet}
Before transforming a variable, ask what it measures. A ratio, a level, a
spread, and a count do not all admit the same operations, and the code will
not stop you from applying the wrong one.
:::

## What to take from this

1. The series IDs are the easy part. Reconciling **frequency** and
   **coverage** is where the actual work is, and it is invisible until you
   download.
2. `start=` is a request, not a promise. Always verify the window you got.
3. Aggregate flows by summing and levels by averaging — the choice is
   determined by what the series measures, not by convenience.
4. Correlate changes, not levels, unless you have a reason to do otherwise.
